# Robert Potts — portfolio site

A small, fast portfolio for the literary critic Robert Potts: an **About** page, a
searchable **Journalism** archive, and an **Editing** page. Built with
[Astro](https://astro.build) and output as plain static files, so it hosts for **free** on
GitHub Pages, Netlify, or Cloudflare Pages.

## Getting started

```bash
npm install      # once
npm run dev      # local dev server (hot reload)
npm run build    # production build → dist/
npm run preview  # serve the built dist/ locally
npm run convert  # convert Word docs → HTML fragments (see below)
```

Node 18.20+ (or 20/22+) is recommended.

## How it fits together

```
content-src/docx/        Robert's raw .docx files (input to the converter)
scripts/convert-docs.mjs  docx → HTML fragment + extracted images
src/
  data/pieces/<slug>.json   metadata for one piece (hand-authored, in git)
  pieces/html/<slug>.html    converted body (generated by the converter)
  content.config.ts          schema that validates the metadata
  styles/tokens.css          THE THEME — colours, fonts, tag colours
  styles/global.css          base styles
  layouts/BaseLayout.astro   <head>, fonts, and the persistent top bar
  components/                TopBar, PageHeader, PieceCard, TagBadge
  pages/
    index.astro              About Me (bio, links, featured "hero" piece)
    editing.astro            Editing
    journalism/index.astro   archive: frozen title + search + focus carousel
    journalism/[slug].astro   one reading page per piece (own shareable URL)
public/images/pieces/      card thumbnails + any images pulled from the docs
```

Each piece is identified by its **slug** (the file name). The slug is the URL
(`/journalism/<slug>`) and the key that joins metadata (`src/data/pieces/<slug>.json`) to
its converted body (`src/pieces/html/<slug>.html`). Keep slugs stable — they are what
people link to.

## Adding a new piece

1. Save the Word document as `content-src/docx/<slug>.docx` (e.g. `the-uses-of-difficulty.docx`).
2. Run `npm run convert`. This writes `src/pieces/html/<slug>.html` and extracts any
   embedded images to `public/images/pieces/<slug>/`. It prints a reminder if the piece
   has no metadata yet. It never overwrites metadata, so it is safe to re-run.
3. Create `src/data/pieces/<slug>.json` (copy an existing one) and fill in:

   ```json
   {
     "headline": "The Uses of Difficulty",
     "subheading": "One sentence that draws the reader in.",
     "type": "Review",                 // Article | Blog | Interview | Obituary | Review
     "date": "2026-05-18",             // YYYY-MM-DD
     "image": "/images/pieces/the-uses-of-difficulty.svg",
     "featured": true                   // optional; at most one piece — shown on About
   }
   ```

   Add `"draft": true` to keep a piece out of the archive.
4. Add the card thumbnail referenced by `image` to `public/images/pieces/`.
5. `npm run dev` to preview, then commit.

The pieces currently in the repo are **placeholder samples** (clearly-marked lorem, with
SVG placeholder thumbnails) so the site runs before real documents are added. Replace them
with real content — and update the bio in `src/pages/index.astro`, the prose in
`src/pages/editing.astro`, and the Substack / LinkedIn URLs at the top of
`src/pages/index.astro`.

## Changing the look

Everything visual — the two fonts, every colour, and the colour of each piece-type tag —
lives as CSS custom properties in **`src/styles/tokens.css`**. Edit that one file to
re-skin the whole site. The current theme is "Ink & Cream" (warm paper, ink text, burgundy
accent, Cormorant Garamond + EB Garamond).

## Deploying

`npm run build` produces a fully static `dist/`. Point any static host at it:

- **Netlify / Cloudflare Pages:** build command `npm run build`, publish directory `dist`.
- **GitHub Pages:** deploy `dist/` (set `site`, and `base` if serving from a sub-path, in
  `astro.config.mjs`).

There is no server or database, so hosting is free on all of the above.
